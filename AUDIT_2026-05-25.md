## 1. Функционални грешки и сигурност

### C1 — Stripe webhook поглъща мълчаливо DB грешки
[api/stripe/webhook.ts:65-70, 82-87, 95-100](api/stripe/webhook.ts#L65-L70)

`await supabase.from('profiles').update(...)` се извиква без проверка на резултата. Ако update-ът падне (RLS грешка, мрежов проблем, profile не съществува), webhook-ът връща 200 и Stripe вечно мисли, че събитието е обработено. **Резултат: потребителят плаща, но не получава Pro план.**

**Fix:** Проверявай `.error` от update и връщай 500 за retry от Stripe (idempotency table вече предпазва от двойна обработка).

### C2 — `storm-alert` Vercel cron работи само веднъж дневно
[vercel.json:55-58, api/cron/storm-alert.ts](vercel.json#L55-L58)

```json
"crons": [{ "path": "/api/cron/storm-alert", "schedule": "0 0 * * *" }]
```

Cron-ът проверява текущ Kp веднъж в денонощието в 00:00 UTC. Повечето geomagnetic storms (Kp ≥ 5) траят 6-18 часа — ако storm започне в 02:00 UTC, ще го пропуснем напълно. Throttling логиката (4 часа между постове) е безсмислена, защото cron-ът така или иначе работи на 24 ч.

**Fix:** Промени на `*/30 * * * *` (всеки 30 мин) или поне `0 * * * *` (всеки час). Throttling логиката вече ще предотвратява спам.

### C3 — Hunt cooldown работи само client-side
[src/pages/Hunt.tsx:69-75, 152-153](src/pages/Hunt.tsx#L69-L75)

```ts
const COOLDOWN_KEY = 'tsw_hunt_last_sighting';
const COOLDOWN_MS = 60 * 60 * 1000;
```

Cooldown-ът пази стойност в `localStorage` — потребител може да го изтрие през devtools и да спамва sightings. Лошо за интегритета на leaderboard-а.

**Fix:** Server-side rate limit в Supabase. Добави колона `last_sighting_at` в `profiles` (или unique constraint върху `aurora_sightings (user_id, date_trunc('hour', created_at))`) и провери в RLS policy или trigger преди insert.

### C4 — Sentry Session Replay записва немаскиран user-generated content
[src/main.tsx:41-46](src/main.tsx#L41-L46)

```ts
Sentry.replayIntegration({
  maskAllText: false,   // ← текст НЕ е маскиран
  blockAllMedia: false, // ← снимки НЕ са блокирани
  maskAllInputs: true,
});
```

С тази конфигурация Sentry записва:
- Описания на aurora снимки (могат да съдържат лична информация)
- Снимки качени в Gallery (потенциално лични)
- Имена на места (домашен адрес на потребител)
- Имена и avatar-и на потребители

**GDPR проблем** — записваме лични данни без съгласие.

**Fix:** Сложи `maskAllText: true, blockAllMedia: true` като default. Селективно показвай само нечувствителни елементи с CSS клас `sentry-unmask`.

### H1 — Gallery: orphan файлове в Storage при изтриване
[src/pages/Gallery.tsx:177-182](src/pages/Gallery.tsx#L177-L182)

```ts
const handleDelete = async () => {
  await supabase.from('aurora_photos').delete().eq('id', pendingDelete.id);
  // ← файловете в storage остават
};
```

Изтриваме само DB реда, не и `aurora-gallery/{user_id}/{photo_id}.jpg` и `_thumb.jpg`. Подути storage разходи + leaked images (URL-ите остават валидни, защото bucket-ът е публичен).

**Fix:**
```ts
await Promise.all([
  supabase.storage.from('aurora-gallery').remove([
    `${pendingDelete.user_id}/${pendingDelete.id}.jpg`,
    `${pendingDelete.user_id}/${pendingDelete.id}_thumb.jpg`,
  ]),
  supabase.from('aurora_photos').delete().eq('id', pendingDelete.id),
]);
```

### H2 — Sitemap не съдържа `/viewing-window`

Страницата е добавена днес, но `scripts/prerender-meta.mjs` не е изпълнен с обновените routes. Sitemap има 336 URL-а но `viewing-window` го няма за никой от 16-те езика — **16 страници не са индексирани**.

### H3 — Hreflang inconsistency между index.html и sitemap.xml
[index.html:16-32, public/sitemap.xml:8-24](index.html#L16-L32)

```html
<!-- index.html -->
<link rel="alternate" hreflang="bg" href="https://www.thestormwatcher.com/?lang=bg" />

<!-- sitemap.xml -->
<xhtml:link rel="alternate" hreflang="bg" href="https://www.thestormwatcher.com/bg"/>
```

Двата формата сочат към различни URL-и. Google ще ги счита за дубликати или ще игнорира hreflang директивите. Освен това `/bg/...` reading е реалния път (vercel.json rewrites го към index.html), докато `?lang=bg` няма поддръжка никъде в кода. Това е **SEO регрес** — не получаваме geo-targeting credit.

**Fix:** Замени всички `?lang=xx` в `index.html` с `/xx`. Това е промяна на 16 реда.

### H4 — Stripe webhook липсва `invoice.payment_failed`
[api/stripe/webhook.ts:55-103](api/stripe/webhook.ts#L55-L103)

Обработваме само `checkout.session.completed`, `customer.subscription.updated/deleted`. Когато месечна такса се провали, Stripe изпраща `invoice.payment_failed` — ние не правим нищо, потребителят остава Pro със счупен subscription.

**Fix:** Добави case за `invoice.payment_failed` — update-ни `subscription_status: 'past_due'` или подобно.

### H5 — Gallery: EXIF orientation не се обработва
[src/pages/Gallery.tsx:24-45](src/pages/Gallery.tsx#L24-L45)

### M4 — storm-alert cron приема CRON_SECRET в query string
[api/cron/storm-alert.ts:53-57](api/cron/storm-alert.ts#L53-L57)

### M7 — AbortError fetch (`/iss`) — Sentry шум
Sentry показва 5 unresolved `TypeError: Load failed` / `AbortError` грешки от `api.wheretheiss.at` и `tle.ivanstanojevic.me`. Потребителят навигира преди fetch да завърши и `useEffect` cleanup не cancel-ва. Не е критично, но замърсява Sentry.

**Fix:** В `useEffect`-и които fetch-ват — добави `AbortController`:
```ts
useEffect(() => {
  const ctrl = new AbortController();
  fetch(url, { signal: ctrl.signal }).catch(e => {
    if (e.name !== 'AbortError') logError(e);
  });
  return () => ctrl.abort();
}, []);
```

### Намерени проблеми (вече описани горе)
- **H2** — sitemap липсва `/viewing-window`
- **H3** — hreflang inconsistency (`?lang=xx` vs `/xx`)
- **L1** — Livestream без BreadcrumbSchema
- **L3** — Page slugs incomplete

### M11 — `<html lang>` не се update-ва при смяна на език
В `index.html` е `<html lang="en">`. Когато потребител превключи на bg/de/zh, `lang` атрибутът остава "en". Screen readers и Google ще четат страницата като английска.

**Fix:** В `LanguageContext` добави:
```ts
useEffect(() => {
  document.documentElement.lang = currentLanguage;
}, [currentLanguage]);
```

### M12 — `noindex` логика за auth pages липсва
Sentry replays включват `/auth`, `/auth/reset` — добре е тези страници да са `noindex` за да не се появят в search results. Provari дали `<PageMeta noindex />` се ползва там.

### L7 — `og-image.webp` не се ползва за всички страници
PageMeta генерира dynamic OG чрез `/api/og?page=...` — но имаме статичен `og-image.webp` като fallback. Provari дали `/api/og` всъщност работи в production (преди имаше проблеми с edge runtime).

## 4. Препоръки за нови функции

Подредени по очаквана стойност за потребителя:

### Висок приоритет

**F1 — Aurora Photo Map**
Покажи всички gallery снимки на интерактивна карта (Leaflet, вече ползваме). Кликаш на pin → виждаш снимката и Kp при заснемане. Дава geographic context на community-то и подтиква user retention.
*Effort: ~4 часа. ROI: висок (visual hook за social sharing).*

**F2 — Aurora Probability Chart (7-day Kp forecast)**
NOAA дава 3-day Kp prediction (вече ползваме). Добави Wing Kp 7-day forecast (`https://services.swpc.noaa.gov/text/wing-kp.txt`). Покажи line chart на `/forecast` или като нова страница.
*Effort: ~3 часа. ROI: висок (Pro feature потенциал).*

**F3 — Solar Cycle Tracker**
Покажи: текуща фаза на Solar Cycle 25, дни от soiar minimum, sunspot count, прогноза за следващ peak (~ февруари 2026 според предсказанията). Educational + retention.
*Effort: ~2-3 часа. NOAA SSN API: `https://services.swpc.noaa.gov/json/solar-cycle/observed-solar-cycle-indices.json`. ROI: среден (научен audience).*

**F4 — ISS Pass Notifications**
ISS-а вече се track-ва (`/iss`). Добави "Notify me when ISS passes overhead". Push notification (вече имаме инфраструктура) когато ISS е в 10° elevation от user-ската локация. Може да е Pro feature.
*Effort: ~5 часа. ROI: висок diferentiator.*

### Среден приоритет

**F5 — Aurora Heatmap Time Slider**
В Aurora Map добави slider "сега → +3 часа → +6 часа" — heatmap се update-ва according to Kp forecast. Показва как зоната ще се движи.
*Effort: ~3 часа.*

**F6 — Community Comments на Sightings**
В Hunt и Gallery добави възможност за коментари на sightings/снимки. Социализация на платформата.
*Effort: ~6 часа (нужна нова таблица `comments`, RLS, UI). Има moderation tax.*

**F7 — Aurora Tours Affiliate Section**
В Livestream и Aurora Map добави "Book aurora tour from {nearest city}". Партньорства с GetYourGuide / Viator. Първи monetization stream освен Stripe subscriptions.
*Effort: ~2 часа за UI, седмици за партньорство.*

**F8 — Cloud Cover Forecast Map**
Open-Meteo дава cloud cover. Покажи heatmap на cloud cover overlay (white = облачно) с opacity, заедно с aurora visibility. Combined view — perfect viewing condition.
*Effort: ~4 часа.*

### Нисък приоритет

**F9 — Geomagnetic Storm Timeline (исторически)**
Покажи бар чарт с последните 30/90 дни на максимален Kp/ден. Educational.
*Effort: ~3 часа. NOAA дава historical data.*

**F10 — Aurora Audio — "Sound of the Aurora"**
Sferics и VLF записи. Аудиоплейър с известни recordings от NASA. Гимик, но "shareable".

**F11 — AR Aurora Predictor** (mobile only)
Capacitor + AR — потребителят насочва телефона си в небето, виждаме "Aurora може да се появи в тази посока".
*Effort: висок. ROI: marketing buzz.*

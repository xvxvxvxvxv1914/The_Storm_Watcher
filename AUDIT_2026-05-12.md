## 🔴 CRITICAL — Решават се ПЪРВИ (1–2 дни)

### C1. Unauthenticated proxy в `api/niggg.ts`
**File:** [api/niggg.ts](api/niggg.ts)
Endpoint-ът проксира POST към `pagmag.ngic.bg/pagcal2.php` без никаква автентикация и rate limiting. Всеки може да го използва като:
- Усилвател за brute-force атаки срещу upstream
- Bandwidth/compute drain → Vercel сметка
- Източник за blacklist на домейна
**Fix:** JWT check + Vercel KV rate limit (10 req/IP/min) + строг whitelist на параметрите.

### C2. Stripe checkout — липсват idempotency keys
**File:** [api/stripe/create-checkout-session.ts:54-65](api/stripe/create-checkout-session.ts#L54)
`stripe.checkout.sessions.create()` няма `idempotency_key`. Double-click или network retry създават дублирани сесии → евентуални двойни такси.
**Fix:** `idempotency_key: crypto.randomUUID()` (или хеш от user+priceId+timestamp-window).

### C3. Stripe webhook — няма replay protection
**File:** [api/stripe/webhook.ts:46-94](api/stripe/webhook.ts#L46)
Подписът се проверява, но `event.id` не се проследява. Прихванато събитие може да се препрати → двойно обработване на абонамент.
**Fix:** Кеш на `event.id` в Vercel KV за 24h: `if (await kv.get(\`stripe:${event.id}\`)) return 200;`.

### C4. Android `allowBackup="true"` — изтичане на потребителски данни
**File:** `android/app/src/main/AndroidManifest.xml`
Пълен device backup → данни от SharedPreferences (сесии, кеш, профил) могат да се извлекат през ADB или Google backup.
**Fix:** `android:allowBackup="false"` + `android:fullBackupContent="false"`.

### C5. CSP `'unsafe-eval'` без оправдание
**File:** [vercel.json:24](vercel.json#L24)
`script-src` разрешава `'unsafe-eval'`, което отваря attack surface за инжектиран код. Нито Stripe.js, нито Vite production build реално го изискват.
**Fix:** Премахни `'unsafe-eval'`. Ако нещо счупи — добавяй конкретно `'nonce-...'` за това място.

## 🟠 HIGH — Преди App Store / Play submission (1–2 седмици)

### H1. Deep-link от Capacitor → отворен redirect
**File:** [src/App.tsx:62-63](src/App.tsx#L62)
```ts
const host = new URL(url).hostname;
if (host) navigate(`/${host}`, { replace: true });
```
`stormwatcher://evil.com` → навигация на `/evil.com`. React Router ще покаже NotFound, но логиката е чуплива.
**Fix:** Whitelist:
```ts
const ALLOWED = new Set(['dashboard','forecast','aurora','alerts','uv','sun','mood','iss','profile','settings']);
if (ALLOWED.has(host)) navigate(`/${host}`, { replace: true });
```

### H2. Stripe checkout origin check — `startsWith` bypass
**File:** [api/stripe/create-checkout-session.ts:20-22](api/stripe/create-checkout-session.ts#L20)
`origin.startsWith(o)` пропуска `https://thestormwatcher.com.attacker.com`.
**Fix:** `ALLOWED_ORIGINS.includes(origin)` (strict equality).

### H3. PlanGuard само client-side
**File:** [src/components/PlanGuard.tsx:19-21](src/components/PlanGuard.tsx#L19)
Проверката е чисто UI. Pro endpoints (ако/когато се добавят) трябва да валидират `profile.plan` от JWT на сървъра.
**Fix:** Helper в Supabase Edge Functions: `requirePlan(req, ['pro','premium'])` преди всеки protected handler.

### H4. Client-supplied `priceId` без whitelist
**File:** [api/stripe/create-checkout-session.ts:31](api/stripe/create-checkout-session.ts#L31)
Stripe ще откаже невалиден ID, но без server-side whitelist няма защита срещу price manipulation атаки.
**Fix:** `ALLOWED_PRICES = ['price_xxx','price_yyy']; if (!ALLOWED_PRICES.includes(priceId)) return 400`.

### H5. Wildcard CORS на всички Supabase Edge Functions
**Files:** `supabase/functions/{delete-account,donki-proxy,submit-mood,send-kp-alerts}/index.ts`
`Access-Control-Allow-Origin: '*'` + destructive operations (delete-account) = повишен attack surface.
**Fix:** Echo на конкретен origin от whitelist: `thestormwatcher.com`, `capacitor://localhost`, `https://localhost`.

### H6. `delete-account` няма rate limit
**File:** `supabase/functions/delete-account/index.ts`
Откраднат JWT → unlimited delete опити.
**Fix:** 1 заявка / user / hour чрез таблица с counter или Edge Function KV.

### H7. Stripe portal session без rate limit
**File:** [api/stripe/create-portal-session.ts](api/stripe/create-portal-session.ts)
Може да се ползва за abuse / logout DoS.
**Fix:** 5 заявки / user / минута.

### H8. Stripe checkout redirect — неvалидиран URL към клиента
**Files:** [src/pages/Pricing.tsx:68](src/pages/Pricing.tsx#L68), Profile.tsx
`window.location.href = data.url` без проверка. Compromised backend → phishing.
**Fix:** `if (!/^https:\/\/(checkout|billing)\.stripe\.com\//.test(data.url)) throw new Error('Invalid');`.

### H9. HSTS заглавие липсва
**File:** [vercel.json](vercel.json)
CSP, X-Frame-Options и пр. присъстват, но няма `Strict-Transport-Security`. Особено важно за auth и payments.
**Fix:** `"Strict-Transport-Security": "max-age=31536000; includeSubDomains; preload"`.

### H10. Email verification gate не се enforces client-side
**File:** [src/contexts/AuthContext.tsx:49-54](src/contexts/AuthContext.tsx#L49)
След signup потребителят може да влиза без `email_confirmed_at`. RLS блокира писане, но UI пропуска четене.
**Fix:** В AuthContext: ако `user && !user.email_confirmed_at` → редирект към „Check your email" страница.

### H11. Sentry — няма `beforeSend` PII филтър
**File:** [src/main.tsx:12-18](src/main.tsx#L12)
Имейл, имена и URL query strings могат да попаднат в Sentry cloud.
**Fix:** `beforeSend(event)` → изтрий `event.user.email`, sanitize `event.request.url`, маскирай query params.

### H12. Android FileProvider — overly permissive path
**File:** `android/app/src/main/res/xml/file_paths.xml`
`<external-path name="my_images" path="." />` дава достъп до целия external storage.
**Fix:** Свий до `path="Pictures/StormWatcher"` или мини на `<cache-path>`.

### H13. iOS — липсват privacy purpose strings за бъдещи permissions
**File:** `ios/App/App/Info.plist`
Имаме само `NSLocationWhenInUseUsageDescription`. Push notifications, photo library (за share aurora screenshots), camera (ако планираме) ще предизвикат App Store reject.
**Fix:** Добави `NSCameraUsageDescription`, `NSPhotoLibraryAddUsageDescription`, `NSUserNotificationsUsageDescription` сега.

## 🟡 MEDIUM — Plan-it work (2 спринта)

### M1. `favorite_locations` без UPDATE policy
**File:** `supabase/migrations/20260425000003_favorite_locations.sql`
Има SELECT/INSERT/DELETE, няма UPDATE — тихи failures при rename favorite.
**Fix:** `CREATE POLICY ... FOR UPDATE USING (auth.uid()=user_id) WITH CHECK (auth.uid()=user_id);`

### M2. Stripe IDs изпратени към client-side `select('*')`
**File:** [src/contexts/AuthContext.tsx:18](src/contexts/AuthContext.tsx#L18), `migrations/20260501..._add_stripe_fields.sql`
`stripe_customer_id`, `subscription_id` се теглят на client.
**Fix:** Explicit `.select('email, full_name, avatar_url, plan')`; Stripe-specific полета само в server endpoint.

### M3. niggg proxy — слаба date валидация
**File:** [api/niggg.ts:10-17](api/niggg.ts#L10)
Regex `^\d{2}-\d{2}-\d{4}$` приема `99-99-9999`.
**Fix:** `new Date(...)` + проверка `isNaN(d.getTime())` + диапазон ±100 години.

### M4. AuroraGlobe — GPU memory leak risk
**File:** [src/components/AuroraGlobe.tsx:147-177](src/components/AuroraGlobe.tsx#L147)
Cleanup разчита на `userData.isAurora` flag. Бъдещ contributor може да забрави и да изтече памет.
**Fix:** Explicit `auroraLayersRef = useRef<THREE.Mesh[]>([])` + iterate ref на unmount.

### M5. `useEffect` exhaustive-deps suppressed на 6 места
**Files:** Aurora.tsx, UV.tsx, ISS.tsx, SunTimes.tsx, MagneticEffects.tsx, Mood.tsx
Някои са оправдани, други — тихи бъгове.
**Fix:** Audit поотделно; премести stable деpends в `useCallback`.

### M6. CSP без `report-uri` / `report-to`
**File:** [vercel.json:24](vercel.json#L24)
Нямаме видимост за CSP violations в prod.
**Fix:** Setup [Sentry CSP reporter](https://docs.sentry.io/product/security-policy-reporting/) или Cloudflare endpoint.

### M7. iOS — `CapacitorHttp: enabled` bypassва ATS
**File:** [capacitor.config.ts:7-9](capacitor.config.ts#L7)
Плъгинът минава покрай native ATS. Ако някой добави HTTP endpoint → тихо ще работи.
**Fix:** Audit всички fetch-ове да минават през стандартен браузерен fetch; CapacitorHttp само за CORS-блокирани GET-ове.

### M8. Android `minSdkVersion=24` (Android 7.0) — EOL
**File:** `android/variables.gradle`
Android 7 e от 2016 г., вече без security patches.
**Fix:** Покачи на `minSdkVersion = 26` (Android 8.0). Pixel/мейнстрийм пазара отдавна е над 8.0.

### M9. iOS — `DEVELOPMENT_TEAM` hardcoded
**File:** `ios/App/App.xcodeproj/project.pbxproj`
Team ID `2W6YCTFKNA` в repo. Дребно изтичане на identity.
**Fix:** Премести в `xcconfig` или Xcode UI; gitignore-ни.

### M10. send-kp-alerts — template interpolation в `.or()` филтър
**File:** `supabase/functions/send-kp-alerts/index.ts:74`
Supabase escape-ва, но pattern-ът е крехък.
**Fix:** Chained `.lt('last_notified_at', cutoff).or('last_notified_at.is.null')`.

### M11. OAuth redirectTo — динамичен `window.location.origin`
**File:** [src/contexts/AuthContext.tsx:123, 133, 143](src/contexts/AuthContext.tsx#L123)
Ако някой хостне сайта на чужд домейн (поглъщане на DNS), OAuth може да върне към него.
**Fix:** Hardcode `redirectTo: 'https://thestormwatcher.com'`.

### M12. Password strength — само client-side
**Files:** [src/pages/Auth.tsx:11-28](src/pages/Auth.tsx#L11), [AuthReset.tsx:8-25](src/pages/AuthReset.tsx#L8)
8 char min, без enforcement сървърно.
**Fix:** Supabase Dashboard → Authentication → Policies → задай минимум 10 char + complexity.

### M13. Stripe.js — няма Subresource Integrity (SRI)
**File:** [vercel.json](vercel.json)
CDN compromise = инжектиран payment код.
**Fix:** Stripe официално не подкрепя SRI (динамичен URL), но трябва да се документира trust assumption.

### M14. `console.error` логва PII в AuthContext
**File:** [src/contexts/AuthContext.tsx:92](src/contexts/AuthContext.tsx#L92)
Сериозно ако заминава в Sentry без филтър (H11).
**Fix:** Маркирай чувствителни полета преди log.

## 📦 npm Dependency Vulnerabilities (18 broj)

```
3 moderate, 15 high
```

Засегнати ключови dependencies:
- **`@vercel/node`** (high × 4) — `path-to-regexp`, `undici`, `minimatch` DoS/injection. Fix: `npm i @vercel/node@^4` (semver major).
- **`@capacitor/assets`** (high) — стара `tar` версия. Hard-pin не помага; чакай fix upstream или мини на manual asset generation.
- **`@xmldom/xmldom`** (high × 3) — XML injection + DoS. Транзитивна през `@trapezedev/project` (Capacitor).
- **`@babel/plugin-transform-modules-systemjs`** (high) — code generation. Транзитивна.
- **`vite`** / **`vitest`** — провери дали актуалните `^7` се засягат.

**План:**
1. `npm audit fix` (non-breaking) — пусни първо.
2. Test build + run app.
3. `npm i @vercel/node@^4` (breaking, изисква code review на API routes).
4. Audit отново.

## 🚀 Не-security подобрения (UX / Performance)

### P1. Globe vendor chunk 1.26 MB → 372 KB gzipped
Aurora глобусът тегли цели three.js + react-globe.gl. **Idea:** dynamic `import('react-globe.gl')` само когато потребителят влезе в Aurora tab. Вече е lazy на компонент-ниво (positive), но цялата three vendor бъндъл се сваля при първи hit. Може да се замени на 2D Leaflet карта за free план, 3D само за Pro.

### P2. Bundle index — 434 KB / 144 KB gzipped
Влиза цяла lucide-react библиотека макар да има `exclude` в vite. Audit реалните импорти.

### P3. PWA precache 1.59 MiB (54 entries)
Изключи още по-агресивно `three-vendor`, `globe-vendor`, `charts-vendor` от precache (вече `globe`/`three` са, но `charts` още е).

### P4. Service worker — offline fallback page
В момента failed fetch → бял екран на iOS. Добави `/offline.html` route в Workbox.

### P5. UpdateCountdown / NextUpdate — N+1 risk
Провери: всеки MetricCard сам ли тегли данни или има shared state? Препоръчвам React Query / TanStack Query за единен cache (L12 в стария audit).

### P6. Globe pause when off-screen
Aurora globe продължава да рендерира при tab switch. `requestIdleCallback` + `useIntersectionObserver` за pause.

### P7. Accessibility audit
- `aria-label` на icon-only buttons (Share, theme toggle) — провери.
- `lang` атрибут на `<html>` се сменя ли при език смяна?
- Кoнтраст в light theme (Prompt 7 предстои) — направи изрично.

### P8. i18n след Prompt 6
В Mood.tsx, UV.tsx, MagneticEffects.tsx добавихме hardcoded BG/EN текстове. Премести в `locales/{bg,en}/*.json` за консистентност.

### P9. Sentry source maps
Потвърди че source maps са upload-нати към Sentry (хем за debug, хем не са public на CDN).

### P10. Pre-commit hooks
`.husky` или `lint-staged` — eslint + typecheck преди commit. Сега ESLint не блокира.

### P11. CI/CD — automated tests
Имаме e2e (Playwright) и vitest. Github Actions, който ги пуска на PR, ще предотврати регресии.

### P12. README + ARCHITECTURE.md
Един високо ниво документ за onboarding (Capacitor сетъп, Supabase env, Stripe webhook setup).
